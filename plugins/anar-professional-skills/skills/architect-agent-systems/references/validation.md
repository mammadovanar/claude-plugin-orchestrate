# Проверка агентной системы

## 1. Статическая проверка

- Каждый trigger различим и не конфликтует с соседними навыками.
- У каждого результата один владелец.
- Роли имеют явные запреты и следующий handoff.
- Источники связаны с конкретными механизмами.
- Детали не дублируются между ядром и references.
- Оркестратор владеет потоком, но не подменяет профессиональных агентов.
- State достаточен для возобновления, но не превращён в полный лог.
- Каждый Loop имеет цель, владельца, обратную связь, изменяемое состояние, бюджет и выход.
- Sequence и branch не оформлены как Loop без необходимости.

## 2. Симуляции

### Типичный сценарий

Дать реалистичный запрос без подсказки ожидаемого маршрута. Проверить выбор слоя, владельца, протокола и артефакта.

### Пересечение ролей

Дать задачу на границе двух компетенций. Система должна выбрать одного владельца, определить консультанта или последовательный handoff и не запустить конкурирующих авторов.

### Высокий риск

Добавить деньги, персональные данные, миграцию, production или необратимость. Система должна увеличить глубину, потребовать доказательства и остановиться на развилке, требующей полномочий пользователя.

### Простая задача

Дать локальное обратимое изменение. Система не должна навязывать полный церемониальный конвейер.

### Возобновление

Прервать процесс после одной стадии. Новый запуск должен восстановить подтверждённое состояние, не повторить завершённую работу и не перескочить gate.

### Loop и антизацикливание

Вернуть результат на два последовательных прохода. Второй проход должен использовать новое доказательство и изменить гипотезу или действие. Затем смоделировать отсутствие прогресса: система должна остановиться по бюджету, сузить проблему или эскалировать, а не повторять ту же попытку.

## 3. Оценка результата

Оценивать по шкале 0–2:

| Критерий | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Маршрутизация | неверная | приемлемая | точная и минимальная |
| Ownership | конфликтует | частично ясен | однозначен |
| Вес процесса | несоразмерен | терпим | соответствует риску |
| Протоколы | декоративны | частично применены | изменили решение |
| Артефакт | общий текст | применим с доработкой | готов к передаче |
| Проверка | отсутствует | формальна | доказательна |
| Handoff | потеря контекста | неполный | продолжим без догадок |
| Loop | повтор без выхода | частично управляем | учится, прогрессирует и завершается |

Не считать систему готовой при нуле по ownership, проверке, handoff или Loop, если Loop необходим задаче. Исправлять механизм, вызвавший сбой, а не добавлять частное правило под тестовый пример.

## 4. Проверка на раздутие

После успешной симуляции удалить всё, что:

- повторяет общеизвестные способности модели;
- не влияет ни на одно решение;
- дублирует другой слой;
- описывает единственный кейс вместо свойства задачи;
- не может быть проверено по выходному поведению.

Повторить симуляцию после сокращения.
