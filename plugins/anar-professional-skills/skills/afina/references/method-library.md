# Библиотека Афины

Выбирать один главный протокол по природе задачи. Подключать максимум два дополнительных только когда они меняют решение.

| Источник | Основной вопрос | Механизм |
| --- | --- | --- |
| Good Strategy / Bad Strategy | В чём настоящая UX-проблема? | Диагноз, направляющий подход, согласованные решения. |
| Cynefin | Насколько определён путь к решению? | Калибровка глубины, эксперимента и стабилизации. |
| The Elements of User Experience — Garrett | На каком уровне находится проблема? | Strategy, scope, structure, skeleton; surface передаётся визуальному слою. |
| Designing for the Digital Age — Goodwin | Как провести продуктовый процесс? | Контекст, роли, цели, сценарии, требования, framework, screen design, validation и handoff. |
| Mental Models | Как пользователь понимает предмет? | Сопоставление структуры продукта с ожиданиями и задачами пользователя. |
| Jobs To Be Done | Какой прогресс пытается совершить человек? | Ситуация, мотивация, desired outcome и конкурирующие способы решения. |
| Domain-Driven Design | Как согласовать UX с доменом? | Язык, bounded contexts, объекты, состояния и инварианты без протекания технических терминов в UI. |
| The Design of Everyday Things — Norman | Понятно ли действие и результат? | Affordances, signifiers, mapping, feedback и error prevention. |
| Don't Make Me Think — Krug | Где интерфейс заставляет разгадывать? | Снижение когнитивной нагрузки, ясность навигации и действия. |
| Nielsen Norman Group | Какие эвристические дефекты мешают потоку? | Visibility, match to real world, user control, consistency, error recovery и recognition. |
| Laws of UX | Как ограничения внимания и памяти влияют на решение? | Fitts, Hick, Miller, proximity, peak-end и другие применимые механизмы. |
| Web Form Design — Wroblewski | Как сделать ввод и validation безопасными? | Порядок полей, defaults, inline validation, ошибки и submit flow. |
| Information Dashboard Design — Few | Как показать управленческое состояние? | Приоритет отклонений, сравнение, плотность данных и честные показатели. |
| Apple HIG / Material Design | Как соблюдать платформенные ожидания? | Навигация, состояния, touch behavior и системные паттерны. |
| WCAG 2.2 | Может ли интерфейс быть воспринят и управляем? | Perceivable, operable, understandable, robust и проверяемые критерии. |
| Design Systems — Kholmatova | Как UX масштабируется? | Повторяемые паттерны, состояния компонентов, governance и консистентность. |
| This is Service Design Doing / Mapping Experiences | Что происходит за пределами экрана? | Frontstage/backstage, journey, ecosystem и межролевые разрывы. |

## Применение

1. Сформулировать вопрос.
2. Извлечь механизм.
3. Проверить применимость.
4. Адаптировать к продукту и роли.
5. Изменить решение.
6. Проверить сценарий после изменения.

При необходимости помечать: `CHANGED_DECISION: <источник> — <что изменилось и почему>`.

Не копировать визуальный стиль источника и не перечислять библиотеку в пользовательском ответе без пользы.
